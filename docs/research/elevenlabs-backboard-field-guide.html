Hotel Caller Field Guide

How ElevenLabs and Backboard fit our agent: find the 5 cheapest hotels, call all 5 at once, handle holds and phone menus, book one room, and email the receipt.

Docs pulled 2026-10-17 · MCP endpoints probed live the same day

Short answers

Q1
ElevenLabs has a full MCP. Backboard only has a docs MCP.

ElevenLabs has a hosted product MCP (OAuth) plus a docs MCP. Backboard's only MCP serves its docs. You use its product through the REST API or backboard-sdk. Note that backboard.ai is a parked domain. The product lives at backboard.io.

Q2
ElevenLabs makes the calls. Backboard is the brain around them.

ElevenLabs Agents + Twilio place the calls and handle the conversation. Backboard covers the LLM work around the calls: hotel search with web search, ranking, summarizing, cross-run memory and token accounting. Neither one sends email or supplies a phone line, so we need Twilio and an email API.

Q3
Yes, the calls run in parallel. They coordinate through our server.

The Creator plan allows 10 concurrent calls. Calls can't message each other directly. Each call uses webhook tools to read and write a shared "race board" on our coordinator. A booking lock there makes sure only one hotel gets booked. A custom-LLM proxy can push state into every turn if we want more.

Q4
Test with one Twilio number and our own phones.

Import a Twilio number into ElevenLabs. Trial accounts need each teammate's phone verified. Then fire 5 outbound-call requests at our own phones with fake hotel details. Each of us plays a receptionist with a different twist: a hold, a phone menu, a request for a card, a voicemail.

Tok
Every LLM call writes one line to a ledger. A script sums it after the email goes out.

Backboard returns token counts on every message. ElevenLabs reports per-model tokens and USD for each call once it finishes processing. Both go into one JSONL file per run, which tally.py turns into the final report.

Q5
English only is the simple case.

Set the agent language to en, pick a natural English voice, and add hotel names as ASR keywords so the agent hears them correctly.

ElevenLabs agents can also consume MCP servers (SSE or streamable HTTP) as tools during a call. We can skip that. Webhook tools are simpler and have lower latency.

2 · Who does what

ElevenLabs Agents

voice, telephony, live conversation
  • Outbound call API: POST /v1/convai/twilio/outbound-call with per-call dynamic variables. Returns conversation_id and callSid.
  • System tools: end_call, skip_turn (stay quiet on hold), play_keypad_touch_tone (phone menus), voicemail_detection, update_state, transfer.
  • Webhook tools: the agent calls our HTTP endpoints during the call.
  • Data collection: pulls typed fields (confirmation number, price, date, address) out of the transcript after the call.
  • Post-call webhooks: transcript, analysis, cost metadata and call-failure events. Signed with HMAC.
  • Batch calling exists, but on our plan it is capped (see Limits). Individual parallel calls work better.

Backboard

LLM brain, memory, token ledger
  • One API key for 17,000+ models. Switch models per message, for example a fast model for ranking and a strong one for messy search results.
  • Web search: web_search: "Auto" on a message. Our hotel search can use it without any browser automation.
  • Tool calling loop: the response comes back with status: REQUIRES_ACTION. You run the tool, submit its output, and repeat until COMPLETED.
  • Memory: stored per assistant and shared across threads. Good for lessons across runs, such as "Hotel X menu: press 2 for reservations".
  • Billing API: input and output tokens and cost per event, plus a summary. This feeds the Learnings score directly.

Gaps neither tool fills: (1) a phone line, since ElevenLabs needs a Twilio number or a SIP trunk and Twilio bills separately. (2) Email, so we pick Resend, SendGrid or Gmail SMTP. (3) A reliable source of hotel prices and phone numbers. Backboard web search can produce a list, but its prices may be stale.

Backboard has no OpenAI-compatible endpoint, so it can't be plugged in as the ElevenLabs agent's LLM directly. Inside the call, the agent uses an ElevenLabs-hosted model.

Stage 2: fan out the calls

python · asyncio, one request per hotel
async def place_call(h):
    body = {
      "agent_id": AGENT_ID,
      "agent_phone_number_id": PHONE_ID,
      "to_number": h["phone"],                       # E.164, e.g. +14165550101
      "conversation_initiation_client_data": {
        "dynamic_variables": {
          "candidate_id": h["id"], "hotel_name": h["name"], "listed_price": str(h["price"]),
          "check_in": CHECK_IN, "nights": str(NIGHTS), "guests": str(GUESTS),
          "guest_name": GUEST_NAME, "guest_email": GUEST_EMAIL,
        }
      },
      "telephony_call_config": {"ringing_timeout_secs": 25},   # default 60
    }
    r = await http.post("https://api.elevenlabs.io/v1/convai/twilio/outbound-call",
                        headers={"xi-api-key": EL_KEY}, json=body)
    return r.json()   # {success, message, conversation_id, callSid}

results = await asyncio.gather(*(place_call(h) for h in top5))

Use dynamic variables rather than overrides. Overrides (prompt, first message, voice) have to be enabled in the agent's security settings first, or the call fails.

Stage 3: capture and email

To save time, send the email as soon as the winning agent calls report_confirmation during the call. Don't wait for post-call analysis. Afterwards, use the post-call webhook's data_collection_results to double-check the values and to send a corrected email if needed.

Prompt skeleton

You are Sam, calling {{hotel_name}} to book a room for {{guest_name}}:
check-in {{check_in}}, {{nights}} night(s), {{guests}} guest(s). Speak like a friendly, brief
human caller. One question at a time. If asked, say you're an AI assistant booking for {{guest_name}}.

Flow:
1. Ask for the best available rate for those dates. Call report_quote(price, currency, available).
2. Before agreeing to book, call claim_booking(price). Do what the result says:
   BOOK -> confirm the booking. DECLINE -> thank them, say you'll call back, end_call.
3. Get the confirmation number, total price, dates and the hotel's street address. Read the
   confirmation number back digit by digit. Call report_confirmation(...). Then end_call.
Phone menus: use play_keypad_touch_tone to reach reservations or the front desk.
On hold: say "Sure, I'll hold" once, then skip_turn until a person speaks.
Card requested: {{payment_policy}}

Data collection fields (backup extraction)

booked (boolean), confirmation_number (string), total_price (number), currency (string), stay_dates (string), hotel_address (string). The limit is 25 fields per agent on our plan.

5 · Can the 5 agents talk to each other mid-call?

Not directly. ElevenLabs runs each phone conversation on its own servers. Over the Twilio integration, we don't hold the conversation socket, and the contextual_update event is sent through that socket. That last point is our reading of the docs, not something they state. So coordination goes through our coordinator, in three layers:

PatternDirectionHowVerdict
A. Race board via webhook toolsAgent pullsEach call calls our endpoints report_quote, claim_booking, report_confirmation and check_status. It passes {{system__conversation_id}} and {{candidate_id}} so we know which call is which.Build this
B. Custom LLM proxyWe push, every turnPoint the agent's LLM at our own OpenAI-compatible /v1/chat/completions (SSE). Each turn we prepend the latest board, e.g. "Hotel 3 is already booked, wrap up politely", then forward to a model. We also get exact token counts.Stretch
adds latency and build time
C. Hard hang-upWe killUse the Twilio REST API: update the call by its callSid to status=completed.Fallback
if a loser won't end the call

Don't use Backboard memory as the live lock. Memory writes are asynchronous: you get a memory_operation_id and have to poll it. A classifier also decides which facts get stored at all. Use it for lessons that last across runs. Keep the race state in our process: a dict plus an asyncio.Lock, or Redis.

Booking policy: first claim wins, with a price guard

sequenceDiagram
  participant H1 as Call 1 (Hotel A)
  participant C as Coordinator
  participant H3 as Call 3 (Hotel C)
  H1->>C: report_quote(129, available)
  H3->>C: report_quote(119, available)
  H3->>C: claim_booking(119)
  C-->>H3: BOOK (lock taken)
  H1->>C: claim_booking(129)
  C-->>H1: DECLINE, wrap up politely
  H3->>C: report_confirmation(ABC123, 119, dates, address)
  C->>C: send email now, end other calls

There is one knob to tune. Fastest: grant the first claim at or under the listed-price ceiling. Cheapest: hold claims for a few seconds while cheaper-ranked calls are still collecting quotes. The agent says "one moment" and calls check_status. Judges rank on both speed and cost, so we should pick one deliberately and log it in decisions.md.

python · coordinator sketch (FastAPI)
board = {"winner": None, "quotes": {}}
lock = asyncio.Lock()

@app.post("/tools/report_quote")
async def report_quote(q: Quote):
    board["quotes"][q.candidate_id] = q
    return {"booking_open": board["winner"] is None,
            "best_price_seen": min(x.price for x in board["quotes"].values())}

@app.post("/tools/claim_booking")
async def claim_booking(c: Claim):
    async with lock:
        if board["winner"] is None and c.price <= PRICE_CEILING:
            board["winner"] = c.candidate_id
            return {"decision": "BOOK"}
    return {"decision": "DECLINE", "say": "Thanks so much, we'll call back if plans change."}

@app.post("/tools/report_confirmation")
async def report_confirmation(r: Confirmation):
    asyncio.create_task(send_receipt_email(r))   # all four required fields
    asyncio.create_task(wind_down_other_calls(except_id=r.candidate_id))
    return {"ok": True}

8 · Token tally for the whole pipeline

Every place that spends tokens appends one line to a per-run ledger (runs/<run_id>/ledger.jsonl). Timing events go in the same file. Once the receipt email is out, tally.py waits for the 5 calls to finish processing, collects their usage, and prints the final report. The race clock stops at "email sent", so the tally never slows the booking down.

Two cross-checks. (1) Backboard's GET /billing/usage/recent?start=YYYY-MM-DD lists every billed event with tokens and amount_deducted_usd, including memory writes and vector reads that a message response doesn't show. Filter it to the run's time window and compare with the ledger. The API is account-wide, so nobody else should use that Backboard key during the run. (2) For each call, the token price values should add up to charging.llm_price. We assume price is in USD; this check confirms it on the first test call.

Tagging. Generate a run_id at start and pass it to every call as a dynamic variable, next to candidate_id. Webhooks and lookups can then be tied back to the right run and hotel. initiated_generation appears to include generations cut off by an interruption, and irreversible_generation only committed ones. That reading comes from the field names, so log both and bill from initiated.

The ledger

python · ledger.py
RUN_ID = time.strftime("%Y%m%d-%H%M%S")
os.makedirs(f"runs/{RUN_ID}", exist_ok=True)
_f = open(f"runs/{RUN_ID}/ledger.jsonl", "a")

def log(kind, stage, **fields):              # kind: "tokens" | "cost" | "stage"
    _f.write(json.dumps({"ts": time.time(), "run_id": RUN_ID, "kind": kind, "stage": stage, **fields}) + "\n")
    _f.flush()

@contextmanager
def timed(stage):                            # with timed("search"): ...
    t0 = time.time(); log("stage", stage, event="start")
    try: yield
    finally: log("stage", stage, event="end", wall_ms=round((time.time() - t0) * 1000))

def log_backboard(stage, r):                 # call right after every Backboard response
    log("tokens", stage, source="backboard", model=f'{r["model_provider"]}/{r["model_name"]}',
        input=r.get("input_tokens", 0), cached_input=r.get("cached_input_tokens", 0),
        cache_write=r.get("cache_write_input_tokens", 0), output=r.get("output_tokens", 0),
        cost_usd=r.get("cost_usd"), ref=r.get("message_id"))
python · collect usage for one call, after the race
async def collect_call(conv_id, candidate_id):
    for _ in range(60):                                        # up to ~5 min for analysis to finish
        c = (await http.get(f"https://api.elevenlabs.io/v1/convai/conversations/{conv_id}",
                            headers={"xi-api-key": EL_KEY})).json()
        if c["status"] in ("done", "failed"): break
        await asyncio.sleep(5)
    md = c["metadata"]; ch = md.get("charging") or {}
    usage = ((ch.get("llm_usage") or {}).get("initiated_generation") or {}).get("model_usage") or {}
    for model, u in usage.items():
        part = lambda k: (u.get(k) or {})
        log("tokens", "call", source="elevenlabs", call=candidate_id, model=model, ref=conv_id,
            input=part("input").get("tokens", 0), cached_input=part("input_cache_read").get("tokens", 0),
            cache_write=part("input_cache_write").get("tokens", 0), output=part("output_total").get("tokens", 0),
            cost_usd=sum(part(k).get("price", 0) for k in ("input", "input_cache_read", "input_cache_write", "output_total")))
    log("cost", "call", source="elevenlabs", call=candidate_id, ref=conv_id,
        llm_usd=ch.get("llm_price"), platform_usd=ch.get("platform_price"),
        analysis_usd=((ch.get("analysis") or {}).get("total") or {}).get("price"),
        total_usd=md.get("cost_fiat"), duration_s=md.get("call_duration_secs"),
        tts_chars=(ch.get("tts_usage") or {}).get("total_characters"))

A call that never connected (a call_initiation_failure webhook, or an outbound request that failed) gets one cost line with zeros, so the report still shows all 5 rows.

9 · Open questions and risks

  • Card guarantee. Real hotels will ask for a card. The agent must never speak card numbers. Ask the organizers what to say: "pay at check-in", or a test card they provide.
  • "No ready-made agents". We write the prompt, tools and orchestration ourselves, and ElevenLabs is a sponsor, so this should be fine. Confirm with the organizers anyway. Don't use Backboard's R-CLI in the pipeline, since it is a ready-made agent.
  • Double-booking real hotels. The booking lock limits us to one booking. The other 4 calls must end without committing to anything.
  • AI disclosure. The agent answers truthfully if asked whether it's an AI. That's better for judging and for compliance.
  • Real or simulated hotels? If the organizers run the "hotels", their front desks may test phone menus and holds on purpose. Plan for both.
  • Email provider and hotel data source are still undecided. Both go in decisions.md.
  • Pre-build everything. Agent, phone import and webhooks get created before the start. The live run should only search, dial and email.
